# Native TV player
Use latest verified compatible stable AndroidX Media3 ExoPlayer, MediaSession and native MediaCodec; prefer SurfaceView and official Compose media surface with TV Material controls. No external player dependency or duplicate playback engine. Hardware first, capability-based software fallback only for verified gaps. Preserve HDR and audio passthrough only where supported. Select tracks, language, embedded/external subtitles (SRT ASS SSA WebVTT TTML PGS VobSub subject to actual support), matching sidecar discovery, explicit file selection, caption preferences and offset where supported. Bitmap captions retain authored appearance; do not promise arbitrary styling. Resume position, speed, seek, aspect ratio, playlist, fullscreen, D-pad controls, accessible focus and deterministic back. Use MediaSession and audio focus, release player/surface on lifecycle exit, keep screen awake only during playback, handle noisy audio and interruptions. Local content URI and provider-backed seekable DataSource for network; bounded buffers, cancellation, reconnect, no whole-file downloads. Avoid TextureView unless required. Frame-rate matching through supported platform APIs, no forced refresh or HDR. Test track selection, malformed subtitles, missing codecs, seek, lifecycle, network loss, low memory, focus, HDR/audio capability matrix. Evaluate FFmpeg/libass and other extensions only after license, patent, ABI and performance review. No claims of universal codec support. Persist resume/settings locally; no telemetry. Validate dependencies against official release notes before pinning.

## Default TV caption appearance
Use Media3 SubtitleView and CaptionStyleCompat: yellow #FFE600 text, black outline, transparent background/window, sans-serif-medium, fractional text size 0.0533 by default (0.04/0.07 alternatives), bottom padding 0.08. Override embedded text styles and sizes for consistent readability; bitmap subtitles retain authored appearance. Outline thickness is controlled by Media3. Validate visual contrast, ASS layout and TV viewing distance; no custom subtitle renderer.

## Media engine recovery and track diagnostics (2026-11-25)
Use the existing Media3 load-error policy for automatic loading retries; preserve typed DataSourceException for invalid SMB seek positions so permanent range errors are not retried as transport failures. Manual Retry on an existing failed player uses prepare() instead of replacing the session. Video tracks expose supported selections and automatic selection. Sources: https://developer.android.com/reference/androidx/media3/datasource/DataSourceException ; https://developer.android.com/reference/androidx/media3/exoplayer/upstream/DefaultLoadErrorHandlingPolicy ; https://developer.android.com/media/media3/exoplayer/customization . CI and connection interruption validation pending.

## SMB replay safety
Only explicitly read-only directory listing and opening a read-only handle may be automatically replayed after confirmed connection loss. Upload, download-to-provider, mkdir, rename and delete must not replay the entire operation after an ambiguous failure; report the failure and allow explicit refresh/reconciliation. Media3 retains its native load retry policy and offset-based reads. Regression tests verify replay policy and cancellation; actual network interruption remains a separate runtime acceptance requirement.

## Native format acceptance matrix
The emulator runtime matrix exercises MP4/H.264 with external SRT, WAV/PCM, and Matroska/H.264/AAC with embedded SRT, locally and over SMB in debug/minified variants. Verify rendered frame, selected AAC track and active embedded cue; do not infer hardware acceleration, HDR, passthrough or universal codec support from emulator success. Preserve Media3 default capability-aware codec/track selection (https://developer.android.com/media/media3/exoplayer/supported-formats and https://developer.android.com/media/media3/exoplayer/track-selection). FFmpeg is used only to generate synthetic CI fixtures, not shipped in the APK.
