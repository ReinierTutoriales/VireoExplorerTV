# Governance

Apply AGENTS.md and docs/EXECUTION.md as canonical project contracts.

## Repository integrity
- Inspect current remote HEAD, active branches, PRs and repository rules before every work batch. Reuse the active authorized branch when scope matches; avoid parallel overlapping branches and redundant PRs.
- Keep changes cohesive and reviewable. Delete obsolete code, resources, dependencies and workflows only after checking consumers and preserving required history and functionality.
- Preserve actual authenticated authorship, signatures, licenses, upstream credits and repository protections. Never impersonate the owner, fabricate signatures or bypass protections. Avoid promotional tool attribution.
- Integrate, release, delete branches or change signing, identity, application ID or version only when authorized. Use short descriptive branch names without tool/model names.
- Latest compatible stable dependencies are standing policy; verify release and artifact availability before changing them.

## Efficient execution and accountability
- Apply precise-coding and testing-discipline before editing. Complete the maximum safe, coherent in-scope implementation rather than repeatedly stopping after one minor correction.
- Audit all affected components and confirmed failures together. Resolve root causes and their adjacent manifestations, not just the first reported symptom. Do not broaden scope with speculative changes.
- Prefer official implementations over redundant custom code; use documented platform capability baselines rather than device-specific assumptions.
- Do not count plans, comments, tests alone or documentation changes as functional repairs. Report completed actions only after verification.
- If a failure is verified, correct its cause and regression coverage; update the relevant skill with one durable lesson only when existing rules do not already cover it. Replace obsolete guidance instead of appending duplicates.
- Verify actual remote state after publishing. Record exact SHA, changed files, available run URLs, verified checks and remaining blockers. Pending checks are not passed checks.
- If access or execution is blocked, perform independent safe work that remains available; disclose what could not be verified. Never claim future or background work without an actual execution mechanism.

## Project contracts
The proprietary license, owner release/signing decisions and repository protections are binding. Distinguish implementation, specification and measured evidence. Follow docs/EXECUTION.md and its applicable specification routing.
